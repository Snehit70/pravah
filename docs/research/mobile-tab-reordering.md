# Mobile tab reordering on React Native 0.85 and Reanimated 4.3.1

**Scope.** This note compares the current Pravah tab editor with current first-party and maintained React Native reorder examples. Pravah's exact mobile stack is React Native 0.85.3, Expo 56.0.12, Gesture Handler 2.31.1, Reanimated 4.3.1, and Worklets 0.8.3. No production code or dependency was changed.

## Findings

### What the current implementation does

- The current working tree uses `Gesture.Pan()` on each whole tab card, with `activeOffsetX([-8, 8])` and `failOffsetY([-12, 12])`, and drives positions with Reanimated shared values and reactions. It does not use `PanResponder`. The earlier draft's claim that the implementation still uses `PanResponder` is stale. See [SettingsSheet.tsx:487-699](../../apps/mobile/src/components/SettingsSheet.tsx#L487-L699).
- The settings parent is a plain React Native `ScrollView`. It has no `scrollEnabled` prop tied to drag state. The earlier draft's claim that the parent is disabled during drag is also stale. See [SettingsSheet.tsx:3423-3436](../../apps/mobile/src/components/SettingsSheet.tsx#L3423-L3436).
- Capture is outside the reorderable data. The four persisted `TabKey` values are rendered as separate card siblings, while Capture is a fixed absolute center slot with `zIndex: 4`. See [SettingsSheet.tsx:837-857](../../apps/mobile/src/components/SettingsSheet.tsx#L837-L857) and [SettingsSheet.tsx:4310-4353](../../apps/mobile/src/components/SettingsSheet.tsx#L4310-L4353).
- The current code has a likely drop snap-back bug. On a successful drop, the active card is moved to the target, but `onFinalize` clears `activeSourceIndex` while leaving `activeTargetIndex` set. The reaction then sends non-active cards back to their source slots because `tabOrderVisualIndex` receives an inactive source. The JavaScript `onReorder` callback is queued separately and can then move the cards to the committed order. This can show as a short snap-back or double animation on release. See [SettingsSheet.tsx:533-553](../../apps/mobile/src/components/SettingsSheet.tsx#L533-L553) and [SettingsSheet.tsx:595-637](../../apps/mobile/src/components/SettingsSheet.tsx#L595-L637). This is a static code finding, not a device observation.
- The parent-scroll contract is not explicit. The child pan has a vertical failure threshold, but there is no Gesture Handler relation to the parent scroll gesture. The `Pan` API documents `simultaneousWithExternalGesture`, `requireExternalGestureToFail`, and `blocksExternalGesture`; the exact relation must be tested on both platforms. See [Gesture Handler 2.x Pan configuration](https://docs.swmansion.com/react-native-gesture-handler/docs/2.x/gestures/pan-gesture/#config).

### Official Reanimated and Gesture Handler examples

- Reanimated's official compatibility table and versioned `compatibility.json` put Reanimated 4.3.x on React Native 0.81 through 0.85 and Worklets 0.8.x. Pravah's exact versions are in that supported range. Reanimated 4 also requires the New Architecture. See [compatibility table](https://docs.swmansion.com/react-native-reanimated/docs/guides/compatibility/), [Reanimated 4.3.1 compatibility.json](https://github.com/software-mansion/react-native-reanimated/blob/4.3.1/packages/react-native-reanimated/compatibility.json), and [Worklets 0.8.x compatibility.json](https://github.com/software-mansion/react-native-reanimated/blob/4.3.1/packages/react-native-worklets/compatibility.json).
- The Reanimated 4.3.1 source tree does not contain an official sortable-list component. Its official examples are `DragAndSnapExample` and `GestureHandlerExample`, which demonstrate `Gesture.Pan`, shared values, `useAnimatedStyle`, and spring settling. They do not implement neighbor movement, a fixed center item, or nested parent scrolling. See [DragAndSnapExample.tsx](https://github.com/software-mansion/react-native-reanimated/blob/4.3.1/apps/common-app/src/apps/reanimated/examples/DragAndSnapExample.tsx), [GestureHandlerExample.tsx](https://github.com/software-mansion/react-native-reanimated/blob/4.3.1/apps/common-app/src/apps/reanimated/examples/GestureHandlerExample.tsx), and [Handling gestures](https://docs.swmansion.com/react-native-reanimated/docs/fundamentals/handling-gestures/).
- Gesture Handler's versioned 2.x documentation is the right reference for Pravah's 2.31.1 package. That page now carries a banner saying 2.x is no longer actively maintained and points readers to 3.x. The documented `Pan` options still match the current code's horizontal activation and vertical failure strategy. See [Gesture Handler 2.x Pan gesture](https://docs.swmansion.com/react-native-gesture-handler/docs/2.x/gestures/pan-gesture/).

| --- | --- | --- | --- | --- |
| Official Reanimated 4.3.1 example | No | No | Pravah's core versions are in Reanimated's compatibility matrix | Useful primitive only, not a drop-in list |

## Recommendation

Keep the current custom Gesture Handler and Reanimated approach for the immediate fix. It already matches Pravah's four-card data contract, keeps Capture outside that contract, and avoids a nested virtualized list. First fix the drop-state transition and verify the parent-scroll relation on iOS and Android.

If the goal is to remove the custom fixed-slot code, prototype `react-native-sortables@1.10.0` with `Sortable.Flex` as a separate dependency experiment. It is the only candidate in this comparison with a first-party fixed middle item and a documented animated parent-scroll integration. Do not call it a drop-in replacement: its own current test stack is newer than Pravah's, and its README still warns about a Gesture Handler 2.x New Architecture issue where a dragged item can remain stuck after a screen detaches. See [issue #349](https://github.com/MatiPl01/react-native-sortables/issues/349).

Do not replace this editor with `react-native-draggable-flatlist@4.0.3` or `react-native-reorderable-list@0.18.1` based on the available evidence. Neither matches the fixed center action as cleanly, and RNDFL already fails in this app's recorded Reanimated 4 test.
